# 资料流：从收据到 bINT

## 1.3 资料流：从收据到 bINT

一张收据的旅程分为两个阶段。

**阶段 A — 同步流程（使用者正在等待）：**

1. 客户端将档案传送至上传端点。伺服器压缩图片、移除 EXIF 中继资料，并将结果存入物件储存。分析前会先检查感知杂凑（perceptual-hash）去重索引。
2. 对于图片输入，视觉 LLM（02 阶段 2）在单次呼叫中直接从图片读取收据。对于 PDF 输入，OCR 层（02 阶段 1）先提取文字，再送入同一个 LLM 阶段。
3. LLM 回传**带标签的纯文字**：商家、日期、总额与付款栏位以一组 `FIELD: value` 行呈现，品项则以管线分隔（pipe-separated）表格呈现。解析为防御式——缺失或格式错误的行使该栏位保持 `null`，管线继续执行。
4. 正规表示式/规则层（02 阶段 3）核对总额并验证日期。
5. 商家解析器（02 阶段 5）附加商家身分。
6. 信任层（03）对收据品质进行分类，奖励在同一请求内计算，使用者因此同时看到已验证的预览与奖励。

**阶段 B — 非同步流程（背景结算）：**

7. 背景后处理工作者使用资料库端模糊比对搭配 LLM 备援，将每个品项解析为标准商品 ID（02 阶段 4），并将该收据的品质分类并入使用者的累积信任分数。
8. 结算工作者汇总符合条件的 bINT 额度、套用每日上限，并为对应的 INT 领取权产生 epoch 分配根。
9. 分配根会提交至链上。索引器将由分配器完成的 INT 领取转帐回写确认至链下分类帐。

使用者在数秒内看到阶段 A。阶段 B 以非同步方式完成。链下 bINT 分类帐仍是贡献额度的真实来源；链上分配根与领取转帐则记录对应的 INT 分配。
