# 可扩展性假设

## 1.8 可扩展性假设

本节以工作负载变数表达容量。架构将使用者数量、收据密度、品项数量、重试率与批次策略一并评估。

| 符号 | 意义 |
|---|---|
| `U` | 每日活跃使用者 |
| `r` | 每位使用者每日平均收据数 |
| `a` | 提交处理的收据占比 |
| `L` | 每张收据平均品项数 |
| `v` | 符合奖励资格的已验证收据占比 |
| `e` | 每张收据平均事件记录数 |
| `p` | 以 PDF 提交的收据占比（OCR 路径） |
| `ρ_ocr` | OCR 重试率 |
| `ρ_llm` | LLM 重试或自我一致性率 |
| `B` | 链上结算批次大小 |

每日处理收据量：

```text
R_d = U × r × a
```

每月热资料成长约略值：

```text
Rows_m ≈ 30 × R_d × (1 + L + e)
```

每日模型呼叫量：

```text
OCR_d ≈ R_d × p × (1 + ρ_ocr)
LLM_d ≈ R_d × (1 + ρ_llm)
```

每日奖励与结算量：

```text
Verified_d ≈ R_d × v
Onchain_batches_d ≈ ceil(Verified_d / B)
```

公开变动成本公式：

```text
Cost_d ≈ OCR_d × c_ocr + LLM_d × c_llm + Storage_d × c_storage + Settlement_d × c_chain
```

容量决策透过共同测量 `U`、`r`、`L`、重试率与批次策略制定。数值门槛与供应商特定成本系数保留于营运规划中。
