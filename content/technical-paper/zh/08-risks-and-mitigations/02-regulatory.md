# 监管风险

## 8.2 界面

Yumo Yumo 横跨资料产品、使用者贡献与代币经济界面运作，因此多个监管框架触及协议：

| 框架 | 技术界面 | 公开控制原则 |
|---|---|---|
| KVKK | 土耳其的使用者身分、收据内容与处理者清册 | 资料最小化与法律程序记录 |
| GDPR | 欧盟/欧洲经济区使用者资料与汇总资料产品 | 使用者权利流程与汇总发布纪律 |
| MiCA | INT 在欧盟作为加密资产的分类 | 区域注册与法律顾问 |
| 美国代币分类 | INT 功能性代币设计与分配模型 | 贡献连结发放、公开归属与功能性姿态 |
| 税务分类 | 使用者奖励、企业收益、增值税/销售税 | 区域特定会计与申报流程 |

这些框架可在不同区域对相同技术机制赋予不同的合规义务。技术文件定义可承载这些义务的架构界面。

## 8.3 控制模型

**资料最小化。** 收据内容存放于链下资料层（04 §4.16）。链上层承载 INT 领取转帐、epoch 分配根与摘要承诺。完整性证明在产生的同时，使用者消费历史不进入公开链资料。

**汇总发布政策。** B2B 资料产品遵循 k-匿名性与汇总发布规则（05 §5.8）。发布资料产生区域/期间/类别层级讯号，而非个别收据曝光。

**企业结构。** Yumo Yumo Inc. 为德拉瓦州公司（00 §0.1）。区域注册、代表与服务提供者关系伴随法律顾问与产品推广计划进行。

**代币分类姿态。** INT 的经济设计围绕功能性与贡献机制建构：发放与可测量贡献绑定（4.3）、质押奖励来自公开池（4.6）、回购销毁由营运收益资助（4.9）。

## 8.4 演化

随著渐进式在地化推进，合规责任附著于权限迁移计划（00 §0.2、04 §4.10）。企业结构、资料托管与代币服务角色设计为在同一架构下移动至区域结构。
