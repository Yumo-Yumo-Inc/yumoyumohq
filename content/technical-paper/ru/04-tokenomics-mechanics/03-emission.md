# Эмиссия вознаграждений пользователям

## 4.3 Как вознаграждения поступают в bINT

Пул вознаграждений пользователей (User Rewards) управляется таблицей распределения из 4.17. Внутри этого пула ежедневная эмиссия измеряется кривой, основным входом которой является ежемесячная активная аудитория (MAU). У кривой есть три свойства, достойных упоминания:

- **Пошаговый рост к пику.** По мере роста MAU через определённые диапазоны ежедневный эмиссионный пул расширяется ступенями, а не непрерывно. Это позволяет избежать эффекта обрыва, когда активность колеблется вблизи границы.
- **Ограниченный пик.** Ежедневный пул растёт ступенчато до пикового диапазона, затем удерживается. После пика дополнительный MAU повышает плотность вклада на пользователя. Значения диапазонов калибруются в продакшене и не публикуются.
- **Долгий горизонт.** Рельс вознаграждений пользователей рассчитан на 15-летний горизонт. Доля предложения, выделенная под вознаграждения (64,35 млрд INT, см. 4.17), является бюджетом; кривая — счётчиком.

Ступенчатая функция — диапазоны MAU, значения ежедневного пула для каждого диапазона и переходное поведение — задокументирована в 4.19. Границы диапазонов перенастраиваются по мере развития наблюдаемой активности.

## 4.4 Жизненный цикл конверсии bINT → INT

bINT начисляется вне блокчейна в момент, когда чек проходит уровень доверия (03). Он рассчитывается в INT через периодическую эпоху, а не через пользовательский on-chain-вызов конверсии. Жизненный цикл:

```
accrue  →  settle (epoch)  →  claim  →  INT в кошельке пользователя
```

- **Начисление (accrue).** За каждый чек, в учётном слое вне блокчейна. Сумма определяется оценкой качества чека, скорректированной по здоровью ставкой вознаграждения пользователя, ежедневным потолком по уровню и текущей эмиссионной ступенью.
- **Расчёт (settle).** Каждую эпоху движок суммирует реестр вклада по окну эпохи и конвертирует его в INT по фиксированному коэффициенту 1:1 (4.24). Баллы, заработанные до закрытия окна эпохи, рассчитываются в этой эпохе. Движок строит список распределения, независимый верификатор проверяет его (4.17), а полученный корень публикуется в аудированный дистрибьютор.
- **Получение (claim).** Пользователь забирает свой INT напрямую из дистрибьютора в стандартный SPL-кошелёк, передаваемым. Казначейство удерживает INT до получения; отдельного шага вестинга нет.

Когда суммарное пригодное вознаграждение эпохи превышает глобальный потолок эмиссии, сумма каждого участника пропорционально снижается на один и тот же коэффициент (пропорциональное снижение по мягкому потолку, soft-cap pro-rata, 4.24). Значение глобального потолка управляется на операционном уровне и не публикуется.

## 4.5 Ежедневный потолок в терминах токеномики

Ежедневный потолок bINT задаётся уровнем аккаунта пользователя (03 §3.6) через таблицы по уровням (4.22). Внутри этого потолка положение здоровья пользователя (03 §3.5) умножает ставку вознаграждения за чек. Значения по уровням и отображение здоровья живут на уровне доверия и в операционной конфигурации.

Это разложение важно, потому что оно позволяет протоколу перенастраивать любой из факторов, сохраняя токеномику. Расширение рынка или перебалансировка системы уровней может сдвинуть таблицы потолков; волна злоупотреблений сжимает распределение здоровья и вместе с ним — эффективную ставку вознаграждения.
